\title{SafeContract: Composable Action-Space Monitors\\for VLA Deployment}

\begin{abstract}
Vision-Language-Action (VLA) models predict robot actions from images and instructions, but no standardized action-space monitoring exists for their deployment.
We introduce \texttt{SafeContract}, a design-by-contract~\cite{meyer1992} monitoring toolkit that wraps any VLA policy with composable action-space contracts via a Python decorator.
We show that the monitoring signal from a lightweight action-space contract reveals task-specific behavioral patterns and detects distribution shift.
Bounds enforcement is a byproduct; the primary value is observability.
Controlled ablations demonstrate zero false positives on clean policies while catching all violations on drifting and jerky policies.
Across 130 LIBERO tasks (40 standard + 90 diverse), each task produces a distinct \emph{violation fingerprint} across joint dimensions, with bounds violation rates varying from 4\% to 37\% and velocity violations dominating at 72.4\% of all violations.
Changes in violation rate detect task switches with $p < 0.005$ across all tested pairs.
These findings position action-space monitors as deployment observability tools: violation patterns expose what a VLA ``thinks'' about its action space without requiring model internals.
The full decorator adds ${\sim}$13\,$\mu$s overhead per action, requiring no QP solver, VLM, or model retraining.
We release the toolkit as open source.\footnote{Code: \url{https://github.com/krishnam94/vla-edge}}
\end{abstract}

\section{Introduction}

VLA models~\cite{openvla,smolvla} enable robots to follow natural language instructions by predicting actions from visual observations.
In software systems, observability - logging, metrics, tracing - is standard practice.
VLA deployment has no equivalent for the action space: \textbf{no standardized action-space monitoring exists for VLA outputs}.

This is not theoretical.
OpenVLA's deployment script sends raw neural network outputs directly to motors with zero bounds checking~\cite{openvla}.
pi0's OpenPI streams actions via WebSocket with no validation~\cite{pi0}.
LeRobot's~\cite{lerobot} \texttt{EEBoundsAndSafety} processor is the only existing runtime check, but it is imperative, provides no composition guarantees, and is easy to omit.
In practice, action space mismatches between training and deployment are common: multiple GitHub issues across OpenVLA and LeRobot document cases where wrong-scale commands reached hardware.

We demonstrate the problem empirically: running SmolVLA~\cite{smolvla} on 100 consecutive LIBERO~\cite{libero} observations, \textbf{every observation produces at least one out-of-bounds dimension}, with values reaching 3.70 (Sec.~\ref{sec:exp_a}).

The deeper problem is observability.
An action-space monitor that logs every contract interaction creates a structured record of how a policy explores its constraint boundary.
We show this record is surprisingly rich: different tasks produce distinct violation fingerprints across joints, and shifts in violation rate signal distribution change.
The enforcement mechanism (clipping) is deliberately simple. The value is in what the enforcement boundary reveals about policy behavior.

We introduce \texttt{SafeContract} with three contributions:
\begin{enumerate}
    \item A composable action-space monitoring toolkit via a \texttt{@safety\_contract} Python decorator on any VLA \texttt{predict()} method (Properties~\ref{prop:composition}--\ref{prop:shift}).
    \item Bounds enforcement as a byproduct: zero false positives on clean policies, full violation detection on corrupted ones (Sec.~\ref{sec:ablation}).
    \item Violation fingerprinting as the key insight: 130 LIBERO tasks produce task-specific joint-violation signatures enabling distribution shift detection (Sec.~\ref{sec:fingerprint}).
\end{enumerate}

\section{Method}

\subsection{Safety Contracts}

A safety contract $C = (\mathbf{l}, \mathbf{u}, v_{\max})$ specifies per-joint action bounds and a velocity limit:
$l_i \leq a_i \leq u_i$ for each joint $i$, and $\|\mathbf{a}_t - \mathbf{a}_{t-1}\|_\infty \leq v_{\max}$.

\subsection{Enforcement Order}
\label{sec:enforcement}

Enforcement proceeds in three phases: (1)~clip to per-joint bounds, (2)~clamp velocity (project each joint's delta onto $[-v_{\max}, v_{\max}]$), (3)~re-clip to bounds.
The final re-clip is critical: velocity clamping shifts actions relative to the previous timestep, which can push them outside the original bounds.
Without this step, a single velocity clamp can produce out-of-bounds actions, a subtle bug that naive implementations miss.

The decorator pattern means any existing VLA adapter gains monitoring and enforcement with one line:

{\small
\begin{verbatim}
@safety_contract(action_range=[-1,1],
                 joint_velocity_max=0.1)
def predict(self, image, instruction):
    return self.model(image, instruction)
\end{verbatim}
}

Three modes are supported: \texttt{clip} (silently enforce), \texttt{warn} (log violations), and \texttt{raise} (halt on violation). All violations are logged with timestep, dimension, magnitude, and severity.

\subsection{Composition Properties}

\begin{property}[Composition via Intersection for Per-Joint Bounds]
\label{prop:composition}
For hyperrectangular per-joint bounds contracts $C_1 = (\mathbf{l}_1, \mathbf{u}_1)$, $C_2 = (\mathbf{l}_2, \mathbf{u}_2)$, sequential clipping equals intersection clipping:
$\text{clip}(\text{clip}(\mathbf{a}, C_1), C_2) = \text{clip}(\mathbf{a}, C_1 \cap C_2)$.
For per-joint bounds constraints, stacking multiple \texttt{@safety\_contract} decorators is order-independent.
\end{property}

\textit{Proof.} Follows from idempotence and commutativity of per-dimension $\min$/$\max$. Verified empirically: sequential clipping through two contracts matches intersection clipping on 200 random-walk sequences (1{,}482 violations). \hfill $\square$

\begin{property}[Feasibility from Safe States]
\label{prop:deadlock}
Let $\mathbf{a}_{t-1}$ satisfy contract $C$ with $v_{\max} > 0$. Then the feasible set is non-empty, since the ``hold position'' action $\mathbf{a}_t = \mathbf{a}_{t-1}$ satisfies both bounds and velocity constraints.
\end{property}

\noindent\textbf{Remark (Velocity Composition).}
Property~\ref{prop:composition} applies to per-joint bounds only.
When stacking contracts with different velocity limits, the intersection semantics require taking $v_{\max} = \min(v_{\max,1}, v_{\max,2})$ at the contract definition level, not through sequential application.
Sequential velocity clamping through two decorators is order-dependent because the intermediate clipped action changes the velocity reference for the second decorator.
Users who need multiple velocity constraints should merge them into a single contract with $v_{\max} = \min_i(v_{\max,i})$.

\begin{property}[Shift Detection Bound]
\label{prop:shift}
For a stationary policy $\pi$ and fixed contract $C$, let each step produce an independent Bernoulli violation indicator with true rate $r^*$. By Hoeffding's inequality~\cite{hoeffding1963}, the empirical violation rate $\hat{r}_w$ over a window of $w$ steps satisfies
\begin{equation}
\Pr\!\bigl(|\hat{r}_w - r^*| > \epsilon\bigr) \;\le\; 2\exp\!\bigl(-2w\epsilon^2\bigr).
\label{eq:hoeffding}
\end{equation}
Setting the right-hand side to $\alpha$ and solving gives $w \ge \ln(2/\alpha)\,/\,(2\epsilon^2)$. At confidence $1{-}\alpha = 0.95$: $w \ge 738$ for $\epsilon = 0.05$, or $w \ge 185$ for $\epsilon = 0.1$. A sustained deviation beyond $\epsilon$ over such a window detects non-stationarity at confidence level $1{-}\alpha$.
\end{property}

\noindent\textit{Caveat.}
Hoeffding's inequality assumes independent trials. VLA action sequences exhibit temporal autocorrelation, so the effective sample size may be smaller than $w$. For $\beta$-mixing processes, the bound degrades by a factor depending on the mixing rate~\cite{yu1994}. In practice, we observe that the concentration holds well empirically (Sec.~\ref{sec:fingerprint}), suggesting sufficient decorrelation at the violation-indicator level even when raw actions are correlated.

\section{Related Work}

\textbf{Training-time safety.}
SafeVLA~\cite{safevla} fine-tunes with constrained RL (83\% violation cost reduction); RobustVLA~\cite{robustvla} adds robust optimization for perturbation resilience. Both require retraining; SafeContract is orthogonal.

\textbf{Inference-time enforcement.}
AEGIS~\cite{aegis} solves a CBF-QP at runtime (0.36\,ms) using VLM scene understanding.
SafeDec~\cite{safedec} applies STL-constrained decoding but requires logit access.
Safety Chip~\cite{safetychip} uses LTL monitors for plan-level constraints.
SafeDiffuser~\cite{safediffuser} and CoDiG~\cite{codig} embed barriers in diffusion denoising.
ATACOM~\cite{atacom} projects onto constraint manifolds for Octo.
Agent Behavioral Contracts~\cite{abc} brings design-by-contract to AI agents but targets discrete LLM decisions, not continuous robot action spaces.

\textbf{Runtime monitoring.}
Sentinel~\cite{sentinel} combines temporal consistency with VLM monitoring to detect failures, but does not \emph{prevent} unsafe actions and requires an additional VLM call.
LIBERO-Plus~\cite{liberoplus} and VLA-Arena~\cite{vlaarena} benchmark VLA robustness under perturbation.
SABER~\cite{saber} demonstrates black-box adversarial attacks on VLAs; SafeContract provides defense-in-depth since monitoring and enforcement operate at the action boundary regardless of input provenance.

SafeContract differs from all the above: (i)~architecture-agnostic; (ii)~explicit composition; (iii)~pure clipping (${\sim}$13\,$\mu$s); (iv)~violation logging as deployment observability.

\textbf{QP equivalence.}
For box constraints $\mathcal{C} = \{\mathbf{a} : \mathbf{l} \leq \mathbf{a} \leq \mathbf{u}\}$, the CBF-QP that AEGIS solves ($\arg\min_{\mathbf{a}' \in \mathcal{C}} \|\mathbf{a}' - \mathbf{a}\|^2$) decomposes into $d$ independent scalar projections, each yielding $\text{clip}(a_i, l_i, u_i)$.
SafeContract's clipping is therefore mathematically identical to AEGIS's QP solution for box constraints.
The distinction is scope: AEGIS handles arbitrary CBF constraints via VLM scene understanding (${\sim}$360\,$\mu$s); SafeContract handles action-space constraints only (${\sim}$13\,$\mu$s), requiring no external perception.

\section{Experiments}

Platform: Apple M3, CPU, Python 3.12. Full contract overhead: 15.6\,$\pm$\,3.8\,$\mu$s (5{,}000 iterations), representing 0.000075\% of SmolVLA inference time. Tighter contracts catch more violations with proportionally more clipping; at the moderate operating point ($\pm 1.0$ bounds, $v_{\max} = 0.1$), mean correction is 0.45 units per action.

\subsection{VLAs Produce Unsafe Actions (EXP-A)}
\label{sec:exp_a}

We run SmolVLA on 100 consecutive LIBERO observations. \textbf{Result}: 100\% of observations produce at least one out-of-bounds dimension, with values from $-2.16$ to $3.70$ (expected $[-1, 1]$). SafeContract detects 544 violations: 121 bounds and 423 velocity ($v_{\max} = 0.1$).

\textbf{Normalization analysis.}
SmolVLA was trained on SO-100 data.
We re-run with correct MEAN\_STD unnormalization.
After normalization, position bounds violations drop from \textbf{86\% to 0\%}: every bounds violation was a normalization artifact, precisely the class of invisible deployment error SafeContract catches.
However, velocity violations persist at \textbf{98\%}: consecutive inferences on different observations produce action jumps exceeding $v_{\max}{=}0.1$ even in correctly scaled space.
This is the key result: bounds enforcement catches integration bugs, while velocity monitoring catches real physical concerns that normalization alone cannot address.

\label{sec:ablation}

The \emph{clean} policy generates actions within bounds with smooth velocity. SafeContract produces \textbf{zero violations and zero modifications}: a safe policy passes through untouched.
The \emph{drifting} policy (cumulative Gaussian noise, simulating distribution shift) produces 115 violations; 42\% of actions are corrected.
The \emph{jerky} policy (random high-frequency spikes) produces 75 velocity violations; 12\% are smoothed.
Post-contract output has zero OOB in all cases.

\textbf{Noise sensitivity.}
Gaussian noise at 7 levels ($\sigma \in \{0, \ldots, 1.0\}$) on 500 ground-truth LIBERO actions confirms calibration: violations scale monotonically from 527 (clean, from fast gripper snaps) to 19{,}269 ($\sigma{=}1.0$), and SafeContract eliminates 100\% at every level (Fig.~\ref{fig:noise}).
Actions modified range from 50.6\% (clean) to 100\% ($\sigma{=}1.0$).

\subsection{Violation Fingerprinting (EXP-H)}
\label{sec:fingerprint}

This experiment is the paper's central finding: violation patterns are informative, not just corrective.

\textbf{Synthetic tasks.}
We simulate four manipulation tasks (reaching, stacking, drawer opening, pouring), each with characteristic action distributions. Each runs for 200 steps with bounds $[-1, 1]$, $v_{\max} = 0.1$.
Each task produces a unique joint-violation fingerprint (Fig.~\ref{fig:fingerprint}): reaching shows broad shoulder/elbow OOB; stacking shows wrist velocity violations; drawer shows a single-joint spike; pouring shows isolated pitch velocity violations.
Fingerprints are stable across 5 seeds (CV $< 0.15$ for 3 of 4 tasks).

\textbf{Shift detection.}
Concatenating two task sequences and computing violation rate in a sliding window of 20 steps, a binomial test yields $p < 0.05$ for all six task pairs ($p < 0.001$ for five of six).

\textbf{Task classification.}
Using cosine similarity between live violation vectors and stored fingerprints, a nearest-centroid classifier achieves 100\% accuracy across 40 trials.

\begin{figure}[t]
    \centering
    \includegraphics[width=\columnwidth]{figures/fig4_fingerprint.pdf}
    \caption{Violation fingerprints across four manipulation tasks. Each task produces a distinct pattern of joint violations, enabling task identification and shift detection from monitor logs alone.}
    \label{fig:fingerprint}
\end{figure}

\textbf{Validation on 130 LIBERO tasks.}
We ran SmolVLA on all 130 LIBERO tasks: 40 from the four standard suites and 90 diverse tasks from LIBERO-90.
Across the 90 diverse tasks, bounds violation rates vary from 4\% (kitchen drawer manipulation) to 37\% (living room mug placement).
Velocity violations dominate at 72.4\% of all violations, compared to 17.7\% bounds violations.
Rotational axes are most violated: pitch (30.6\%) and roll (26.6\%), while lateral motions are least affected: yaw (9.3\%) and y-translation (9.7\%).
The standard suites show consistent patterns:
\emph{spatial} (x=27\%, pitch=38\%) reflects positioning demands;
\emph{object} (y=18\%, pitch=24\%) reflects object manipulation;
\emph{goal} (pitch=38\%, gripper=26\%) reflects goal-directed rotational actions;
\emph{10-task} (pitch=25\%, gripper=21\%) reflects diverse multi-step coordination.
These patterns emerge from the same model on genuinely different tasks, confirming that violation fingerprints reflect task-specific action distributions at scale.

\section{Discussion}

SafeContract provides deployment observability for VLA action spaces: one-line adoption, composable stacking for per-joint bounds (Property~\ref{prop:composition}), ${\sim}$13\,$\mu$s overhead.
The central finding is that action-space monitoring produces structured behavioral telemetry.
Different tasks produce distinct violation fingerprints, and violation rate changes detect distribution shift with high statistical significance.
This positions action-space contracts as a low-cost observability tool requiring no gradient access or activation probing.

The enforcement mechanism itself is deliberately simple - per-dimension clipping.
The controlled ablation confirms it adds no distortion to safe policies while catching all violations in corrupted ones.
But enforcement is a byproduct. The value is in the monitoring signal.

\textbf{Normalization vs.\ monitoring.}
Action normalization (mapping model outputs to the target robot's action space) eliminates most bounds violations.
SafeContract is complementary: it provides velocity enforcement (a physical hardware constraint normalization cannot address), violation traceability for debugging, and distribution shift detection.
When normalization is correct, SafeContract's bounds checks become a passive safety net; the velocity monitoring, logging, and fingerprinting remain the primary value.

\textbf{Monitoring-fidelity tradeoff.}
Tighter contracts catch more violations but clip more aggressively.
On 200 synthetic sequences, violations range from 948 (very loose: $\pm 3.0$, $v_{\max}{=}1.0$, mean clip 0.03) to 2{,}561 (very tight: $\pm 0.3$, $v_{\max}{=}0.02$, mean clip 0.91).
At the moderate operating point ($\pm 1.0$, $v_{\max}{=}0.1$), SafeContract catches 2{,}019 violations while correcting actions by less than half a unit on average.

\textbf{Action-space observability as a deployment primitive.}
SafeContract's violation logs constitute a form of \emph{behavioral telemetry} for VLA deployment, analogous to observability tooling in software (metrics, logging, tracing), behavioral analytics (UEBA) in cybersecurity, or statistical process control (SPC) in manufacturing.
Baseline violation rates characterize normal policy behavior; deviations signal anomalies such as distribution shift, model regression, or integration errors.
The 130-task LIBERO validation shows this at scale: the 4\%-37\% spread in violation rates across tasks, with velocity violations dominating at 72.4\%, provides a deployment-time behavioral signature unavailable from training metrics.
The concentration of violations on rotational axes (pitch 30.6\%, roll 26.6\%) versus lateral motions (yaw 9.3\%, y 9.7\%) reveals systematic patterns in how SmolVLA handles different kinematic dimensions.
To our knowledge, no prior work treats VLA action-space constraint interactions as an observability signal.

\textbf{Limitations.}
(1)~EXP-G and EXP-H synthetic tasks use simulated distributions; real VLA violation patterns may differ.
(2)~No closed-loop evaluation: aggressive clipping could degrade task success. Preliminary closed-loop experiments yielded 0\% success for both raw and contracted conditions, consistent with known checkpoint issues (LeRobot issue \#2354).
(3)~The 100\% OOB finding primarily reflects normalization mismatch.
(4)~The violation rate observation is empirical, not a formal statistical guarantee.

\textbf{Future work.}
PropertyGuard: property-based testing that fuzzes action sequences against contracts.
Cross-architecture fingerprint comparison (SmolVLA vs.\ OpenVLA vs.\ pi0).
Conformal prediction calibration for probabilistic safety certificates.
Closed-loop LIBERO evaluation with task success rates.
