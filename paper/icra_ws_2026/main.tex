\title{How VLAs Fail Differently: Black-Box Action Monitoring\\Reveals Architecture-Specific Failure Signatures}

\author{\IEEEauthorblockN{Krishnam Gupta}
\IEEEauthorblockA{Independent Research \\
San Francisco, CA \\
kayjee1994@gmail.com}}

\maketitle

\begin{abstract}
VLA models predict robot actions end-to-end from vision and language, but what happens between the model's output layer and the robot's motors is largely unstudied.
We present a controlled characterization of how different VLA architectures fail at the action level.
Running VQ-BeT and Diffusion Policy on the same PushT dataset ($n{=}200$, same seeds), we find that VQ-BeT produces 2.4$\times$ more velocity violations than Diffusion (1{,}847 vs.\ 772), that jerk monitoring predicts failure for discrete-token architectures (AUROC${=}$0.88) but not smooth denoisers (0.43), and that direction reversal rate is the most universal predictor (0.93 and 0.79).
No single monitor is universally best - this is not a limitation of monitoring but a property of VLA architectures that deployment infrastructure must accommodate.
We introduce \texttt{SafeContract}, a training-free, black-box action monitoring toolkit with conformal calibration, enabling architecture-matched failure prediction without model access or retraining.\footnote{Code: \url{https://github.com/krishnam94/vla-edge}}
\end{abstract}

\begin{IEEEkeywords}
VLA, action-space monitoring, failure prediction, architecture analysis, conformal prediction, deployment safety
\end{IEEEkeywords}

\section{Introduction}

VLA models~\cite{openvla,smolvla} predict robot actions end-to-end from vision and language, but what happens to those actions between the model's output layer and the robot's motors is largely unstudied.
OpenVLA's deployment script sends raw outputs directly to motors with zero bounds checking~\cite{openvla};
pi0 streams actions via WebSocket with no validation~\cite{pi0};
LeRobot's~\cite{lerobot} \texttt{EEBoundsAndSafety} processor is imperative, uncomposable, and easy to omit.
The implicit assumption is that if the model is good enough, the actions will be safe enough.
We show this assumption is wrong - and that it is wrong in \emph{architecture-specific} ways.

Comparing VQ-BeT and Diffusion Policy on the \emph{same} PushT dataset ($n{=}200$, same seeds), we find architecture-determined failure signatures: VQ-BeT produces 2.4$\times$ more velocity violations (1{,}847 vs.\ 772), jerk predicts failure only for discrete-token models (AUROC${=}$0.88 vs.\ 0.43), and direction reversal rate is the most universal predictor (0.93 and 0.79).
Effective deployment monitoring must be architecture-aware.

We introduce \texttt{SafeContract}, a training-free, black-box action monitoring toolkit with three contributions:
\begin{enumerate}
    \item \textbf{Architecture-specific failure signatures.} Same-dataset comparison ($n{=}200$) reveals that VQ-BeT and Diffusion fail in fundamentally different ways, and that the monitors predicting failure differ by architecture (Sec.~\ref{sec:closedloop}).
    \item \textbf{Architecture-matched failure prediction.} Direction reversal rate achieves AUROC${=}$0.93 (VQ-BeT) and 0.79 (Diffusion); jerk is predictive only for discrete-token models (0.88 vs.\ 0.43). Velocity violations alone yield only 0.69 and 0.41, suggesting that monitor selection matters more than the monitoring paradigm itself (Sec.~\ref{sec:closedloop}).
    \item \textbf{Conformal calibration.} Split-conformal bounds (97.9\% coverage), data-driven velocity limits, and CUSUM shift detection~\cite{page1954} replace hand-tuned thresholds with statistical guarantees~\cite{vovk2005} (Sec.~\ref{sec:monitoring},~\ref{sec:calibration}).
\end{enumerate}

\section{Method}

\subsection{Safety Contracts}

A safety contract $C = (\mathbf{l}, \mathbf{u}, v_{\max})$ specifies per-joint action bounds and a velocity limit:
$l_i \leq a_i \leq u_i$ for each joint $i$, and $\|\mathbf{a}_t - \mathbf{a}_{t-1}\|_\infty \leq v_{\max}$.

\subsection{Enforcement Order}
\label{sec:enforcement}

Enforcement proceeds in three phases: (1)~clip to per-joint bounds, (2)~clamp velocity (project each joint's delta onto $[-v_{\max}, v_{\max}]$), (3)~re-clip to bounds.
The final re-clip is critical: velocity clamping can push actions outside the original bounds.
Any VLA adapter gains monitoring via a one-line \texttt{@safety\_contract} Python decorator on its \texttt{predict()} method.
All violations are logged with timestep, dimension, and magnitude.

\subsection{Conformal Anomaly Scoring}
\label{sec:monitoring}

Beyond binary violation detection, each action receives a conformal p-value measuring its anomalousness relative to the calibration distribution.
Given calibration nonconformity scores $\{s_i\}_{i=1}^n$, the p-value of a new action with score $s$ is $p(s) = |\{i : s_i \ge s\}| / (n+1)$.
Under exchangeability, $P(p \le \alpha) \le \alpha$ for any $\alpha$ - a proper statistical test, not a heuristic~\cite{vovk2005}.
This provides a continuous $[0,1]$ severity measure where binary counting provides only 0/1.
Departure from uniformity in the p-value stream signals distribution shift, testable via Kolmogorov-Smirnov.

\subsection{CUSUM Shift Detection}

We replace ad-hoc EWMA trend tracking with CUSUM~\cite{page1954}, which is Lorden-optimal for detecting persistent mean shifts in sequential data.
The statistic $S_t = \max(0, S_{t-1} + \mathbf{1}[p_t < \alpha] - \alpha)$ accumulates evidence that the anomaly rate exceeds the expected calibration rate $\alpha$.
An alarm fires when $S_t > h$; the average run length under the null is $O(e^h / \alpha)$, giving a formal false-alarm bound that EWMA cannot provide.
On ALOHA demonstration data with conformal p-values feeding the CUSUM, in-distribution actions produce zero alarms; adding $\sigma{=}0.1$ noise triggers detection within 7 steps (threshold $h{=}3$).

Additionally, \textbf{clip magnitude} $m_i = |a_i^{\text{raw}} - a_i^{\text{clipped}}|$ provides a free, per-joint ``wrongness'' signal that remains informative when violation counts saturate.

\subsection{Architecture-Specific Monitors}
\label{sec:health}

Bounds and velocity checks miss architecture-specific failure modes.
We add three targeted monitors:

\noindent\textbf{Stall detection.}
Diffusion policies' primary failure mode is not constraint violation but \emph{policy freeze}: valid-looking micro-movements where the robot barely moves~\cite{safe2025}.
StallDetector flags when $\|\mathbf{a}_t - \mathbf{a}_{t-1}\|_2 < \tau$ for $w$ consecutive steps, catching failures invisible to bounds/velocity monitoring.

\noindent\textbf{Jerk monitoring.}
The third derivative of the action trajectory detects denoising artifacts in flow-matching/diffusion policies and chunk boundary discontinuities in action-chunked policies~\cite{acg2025}.
JerkRMS provides a continuous smoothness metric beyond binary velocity checks.

\noindent\textbf{Direction reversal rate.}
For each joint $j$, a reversal occurs when $\text{sign}(a_{t,j} - a_{t-1,j}) \neq \text{sign}(a_{t-1,j} - a_{t-2,j})$.
The episode reversal rate is the fraction of (timestep, joint) pairs exhibiting a sign change, averaged over all joints.
High reversal rates indicate indecisive or oscillatory behavior - the policy repeatedly changes direction rather than progressing toward the goal.

\noindent\textbf{Gripper oscillation.}
Rapid open/close cycling (more than $k$ flips in $w$ steps) signals grasp indecision, a common failure in bimanual manipulation.
Individual transitions pass velocity checks, but the pattern is pathological.

\subsection{Composition}

For hyperrectangular contracts $C_1, C_2$, sequential clipping equals intersection clipping:
$\text{clip}(\text{clip}(\mathbf{a}, C_1), C_2) = \text{clip}(\mathbf{a}, C_1 \cap C_2)$.
Stacking decorators is order-independent for per-joint bounds; velocity composition uses $v_{\max} = \min_i(v_{\max,i})$.

\subsection{Conformal Calibration}
\label{sec:calibration}

Hand-tuned thresholds are unreliable: a common choice of $v_{\max}{=}0.05$ clips 12.5\% of \emph{expert} actions on the ALOHA dataset.
We replace hand-tuning with split-conformal prediction~\cite{vovk2005}.
Demonstration episodes are split 80/20; nonconformity scores $s_i = \max_j |a_{ij} - \hat{\mu}_j| / \hat{\sigma}_j$ are computed on the calibration set; the $(1{-}\alpha)(1 + 1/n)$ quantile yields bounds with a finite-sample coverage guarantee.
At $\alpha{=}0.05$, conformal bounds are 25\% tighter than the 4$\sigma$ heuristic while achieving 97.9\% holdout coverage (99.5\% per dimension).
Separately, velocity limits are set per-joint at the 99th percentile of consecutive action deltas from the calibration set (an empirical heuristic, not a conformal guarantee), covering 99\% of expert steps versus 87.5\% for the hand-tuned value.

\section{Related Work}

\textbf{Training-time safety.}
SafeVLA~\cite{safevla} and RobustVLA~\cite{robustvla} improve safety via retraining or fine-tuning.
These are complementary to runtime monitoring - a policy can be both trained safely and monitored at deployment.

\textbf{Inference-time safety.}
AEGIS~\cite{aegis} solves a CBF-QP per step (0.36\,ms, requiring dynamics models); SafeDiffuser~\cite{safediffuser} and CoDiG~\cite{codig} embed barriers in diffusion (architecture-specific); SafeDec~\cite{safedec} constrains decoding; Safety Chip~\cite{safetychip} uses LTL monitors; ATACOM~\cite{atacom} projects onto constraint manifolds.
All require either dynamics models, architecture access, or retraining.

\textbf{Failure detection.}
SAFE~\cite{safe2025} trains a failure detector on VLA internal features; FIPER~\cite{fiper2025} trains an RND network for failure prediction; Sentinel~\cite{sentinel} monitors temporal consistency and task progress.
These require training auxiliary models.
SafeContract is the first \emph{training-free, black-box} approach: it monitors only the action output stream, works across architectures without modification, and reveals that failure signatures are architecture-specific.

\textbf{Conformal prediction for safety.}
Recent work validates conformal prediction for robot safety~\cite{safe2025,feldman2025}.
We use split-conformal bounds~\cite{vovk2005} for action-space coverage and conformal p-values with CUSUM~\cite{page1954} for shift detection.
Kim et al.~\cite{kim2026guardrails} argue that modular guardrails are necessary for foundation-model robots; SafeContract provides a concrete, calibrated implementation.

\section{Experiments}

Platform: Apple M3, CPU, Python 3.12. Full monitoring overhead is negligible: $<$0.001\% of typical VLA inference time (${\sim}$13\,$\mu$s per call).

\subsection{VLAs Produce Unsafe Actions (EXP-A)}
\label{sec:exp_a}

We run SmolVLA on 100 consecutive LIBERO observations. \textbf{Result}: 100\% of observations produce at least one out-of-bounds dimension, with values from $-2.16$ to $3.70$ (expected $[-1, 1]$). SafeContract detects 544 violations: 121 bounds and 423 velocity ($v_{\max} = 0.1$).

\textbf{Normalization analysis.}
SmolVLA was trained on SO-100 data.
After correct MEAN\_STD unnormalization, position bounds violations drop from \textbf{86\% to 0\%}: every bounds violation was a normalization artifact.
However, velocity violations persist: at a conservative $v_{\max}{=}0.1$ rad/step, \textbf{16\%} of expert and \textbf{98\%} of SmolVLA consecutive steps violate on at least one joint. The \textbf{6$\times$ gap} is the robust finding; the absolute rates depend on $v_{\max}$ choice.
Bounds enforcement catches integration bugs; velocity monitoring catches physical concerns normalization cannot address.

\subsection{Same-Dataset Cross-Architecture (EXP-CL)}
\label{sec:closedloop}

We evaluate two architectures on the \emph{same} PushT dataset with the same seeds (0-199), contract (bounds $[0, 512]$, $v_{\max}{=}30$\,px/step), and success criterion (coverage ${\ge}0.95$). This controls for task and environment, isolating architecture effects.

\textbf{Diffusion Policy} (262M params, DDPM, $n{=}200$ per condition).
Without SafeContract: 58\% success (116/200, CI$_{95}$: [0.51, 0.65]).
With SafeContract: 57\% success (114/200, CI$_{95}$: [0.50, 0.64]).
Fisher's $p = 0.92$. SafeContract caught 772 violations with no task degradation.

\textbf{VQ-BeT} (37.5M params, VQ-VAE + Behavior Transformer, $n{=}200$).
Without SafeContract: 56.5\% success (113/200, CI$_{95}$: [0.50, 0.63]).
With SafeContract: 54.5\% success (109/200, CI$_{95}$: [0.48, 0.61]).
Fisher's $p = 0.76$. SafeContract caught 1{,}847 velocity violations with no significant degradation.

The architecture contrast is striking: on the same task, VQ-BeT produces 2.4$\times$ more violations than Diffusion (1{,}847 vs.\ 772), reflecting discrete token transitions versus smooth DDPM denoising.

\textbf{Note on success rates.}
Our Diffusion Policy achieves 58\% vs.\ the published 87.4\%. This gap reflects evaluation protocol, not training quality: we use the LeRobot pretrained checkpoint with 300-step episodes and strict coverage $\ge 0.95$ threshold, while Chi et al.\ use 1{,}000-step episodes with relaxed thresholds.
VQ-BeT achieves 56.5\% (published: 57\%), confirming correct reproduction.
The cross-architecture comparison is valid because both models use identical evaluation conditions.

On ALOHA with ACT (51.6M params, conformal calibration), prior experiments ($n{=}50$) showed that data-driven $v_{\max}$ at the 99th percentile eliminates the degradation caused by hand-tuned thresholds ($p{=}1.0$).

Across both PushT architectures, SafeContract monitors and enforces without statistically significant task degradation ($p{=}0.92$ and $p{=}0.76$).

\textbf{Enforcement strictness.}
A preliminary sweep of $v_{\max}$ on ACT (ALOHA, $n{=}20$ per level) shows that over-constrained enforcement ($v_{\max}{=}0.01$) drops success to 0\%, while conformal-calibrated enforcement ($v_{\max}$ at the 99th percentile) falls in the viable range.
The sweep is underpowered for precise operating curves but confirms the expected monotonic trend: excessively tight bounds degrade task success, while data-driven bounds preserve it.

\textbf{Failure prediction.}
Direction reversal rate predicts task failure with AUROC${=}$0.93 on VQ-BeT and 0.79 on Diffusion ($p < 0.001$ both).
Jerk monitoring is strongly predictive for VQ-BeT (AUROC${=}$0.88) but not for Diffusion (0.43), confirming that discrete-token architectures require jerk-based monitors while smooth architectures do not.
Velocity violations alone achieve only AUROC${=}$0.69 (VQ-BeT) and 0.41 (Diffusion), suggesting that a previously reported null result (AUROC${=}$0.54 on ACT using only velocity) may have reflected suboptimal monitor selection rather than a fundamental limit of action-space monitoring (Fig.~\ref{fig:auroc}).

\textbf{Baseline comparison.}
A trivial baseline (total violation count per episode exceeding a threshold) achieves AUROC${=}$0.72 on VQ-BeT and 0.45 on Diffusion.
Architecture-matched monitors improve substantially: reversal rate gains +0.21 on VQ-BeT and +0.34 on Diffusion over this baseline, confirming that monitor selection - not just violation counting - drives predictive power.

\section{Discussion}

The central finding is that \emph{different VLA architectures fail in fundamentally different ways}, and the monitors that predict failure are architecture-specific.
On PushT, VQ-BeT produces 2.4$\times$ more violations than Diffusion (1{,}847 vs.\ 772); jerk predicts failure for discrete-token models (AUROC${=}$0.88) but not smooth denoisers (0.43); conversely, stall detection is the only monitor more predictive for Diffusion than VQ-BeT (0.65 vs.\ 0.52), capturing policy-freeze failures invisible to bounds/velocity monitoring.
A deployment toolkit shipping a single monitor will miss failures on architectures it was not designed for.

\textbf{Implications for VLA deployment.}
The architecture-matched monitoring result has a practical consequence: practitioners must select monitors based on their VLA architecture, not use a one-size-fits-all approach.
For discrete-token models (VQ-BeT, OpenVLA), jerk and reversal rate are the strongest predictors.
For smooth denoisers (Diffusion, flow-matching), stall detection and momentum coherence matter more.
Given a new VLA deployment, the practitioner runs \texttt{from\_demos()} on their demonstration data, wraps \texttt{predict()}, and monitors the CUSUM alarm during rollout; if the alarm fires persistently, they should reduce $v_{\max}$ or switch to a fallback controller.
\texttt{SafetyGuard} integrates all monitors in a single callable, calibrated from demonstration data:

{\small
\begin{verbatim}
guard = SafetyGuard.from_demos(demo_actions)
@guard.wrap
def predict(self, obs): ...
# Every call: clip + stall + jerk + p-value
report = guard.get_summary()
\end{verbatim}
}
\vspace{-2mm}
\noindent No hand-tuning, no model internals, no retraining.
Training-free and black-box: unlike SAFE~\cite{safe2025} and FIPER~\cite{fiper2025}, which require training auxiliary models, SafeContract monitors only the action output stream.

\textbf{Scope.}
SafeContract is \emph{monitoring infrastructure}, not a safety guarantee - it composes with CBF-based workspace constraints~\cite{aegis} and task-level monitors~\cite{sentinel} as the innermost layer of a defense-in-depth stack.
Hand-tuned $v_{\max}{=}0.05$ clips 12.5\% of expert actions; data-driven calibration at the 99th percentile eliminates this ($p{=}1.0$).
The 97.9\% conformal coverage holds under exchangeability with calibration data; during rollout, coverage degrades under distribution shift. CUSUM detects when this occurs; adaptive conformal inference~\cite{gibbs2021} would maintain coverage online.

\textbf{Limitations.}
(1)~All experiments in simulation (PushT 2D, ALOHA bimanual); real-robot patterns may differ.
(2)~Same-dataset comparison on PushT only; cross-dataset results confound architecture with task.
(3)~AUROC results are on PushT (2D); 14-DOF ALOHA validation is in progress.
(4)~Box constraints are necessary but insufficient for full safety; they must compose with workspace-aware methods (CBFs, collision checking) for real deployment.

\textbf{Future work.}
Extending failure signatures to 14-DOF ALOHA manipulation,
adaptive conformal inference for online recalibration,
composite scoring across monitor channels,
integration with CBF-based workspace safety~\cite{aegis},
and real-robot validation on collaborative manipulation tasks.
